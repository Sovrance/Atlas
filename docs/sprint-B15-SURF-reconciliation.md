### Deviations recorded (not silently repaired)

- **D1 — `verify_farkas` and the dual certificate (WP1.4b).** The work order asks for a
  rational Farkas vector `y` with `verify_farkas(A, b, y)` true as the dual certificate of a
  REJECTED point. Farkas' lemma in `pir/symbolic/linear.py` certifies inconsistency of a
  *linear-equality* system; membership in the truncated moment cone is a *conic* (SDP-type)
  condition, so the honest exact dual is a linear exclusion functional `y·μ` that is ≥ 0 on the
  cone — certified by an exact polynomial identity (`Σ y_j x^j = s0 (v0+v1x)² + s1 x^p(1−x)`,
  checked with `verify_solution`) — and < 0 at the point. That is what
  `impossibility_certificate.dual_functional` holds. `verify_farkas` is used where it is a
  genuine certificate: on the Hankel wall the boundary measure is flat (rank 1) and the
  single-atom equality system `[1, x*, x*²] w = μ` is inconsistent → Farkas vector
  (`impossibility_certificate.farkas_atom`). Both (a) negative pivot and (b) dual are required
  and produced; the standalone tool re-checks all three objects.
  *Resolved (§9-OI-8, prereg-003):* accepted as the verifier-layer dual and named as verifier
  op 7, `DUAL_EXCLUSION_FUNCTIONAL` (`docs/verifier-ops-v0.1.md` rev. 1).
- **D2 — `canon.engine.canonicalize` (WP3.2).** Its kinds are `generator`, `choi_qubit`,
  `covariance`, `metric_pair`, all numpy/float based; none applies to amplitude fingerprints
  and floats are barred from the certified path. The R15 rule is implemented as code in
  `b15_surf/gid/fingerprint.py` as the exact orbit-minimum under the dihedral group `D_n`
  (cyclic + reflection). Registered test T2 (relabelled dataset → byte-identical canonical
  features) is the M1-style quotient check.
- **D3 — `pir.candidates.evaluate` verdict for a single compatible family is `PERMITTED`
  ("identified_family"), whereas the work order's Outcome A asks for `FORCED` on the grammar
  label.** The B15-GID *certificate* verdict follows the work order (FORCED only when the
  lattice singles out one family, the DB lookup agrees, δ is recovered and the registered
  thresholds are met at the held-out n); the PIR lattice fact keeps the lattice's own
  vocabulary (`PERMITTED`). Both are stored; no verdict outside SPEC §4 is emitted.
  *Resolved (§9-OI-9, prereg-003 A2) — reversed:* the certificate now also emits `PERMITTED`
  (menu-relative identification); `FORCED` is kept only for δ, which the constraints fix uniquely.
- **D4 — `lattice_fact` hard-codes namespace `invariant` / layer `UNIVERSAL` / E1.** The GID
  forest is re-homed with `dataclasses.replace` to namespace `analyst`, layer `DOMAIN`, with a
  declared measurement interface (work-order §6). No `global:` promotion anywhere.
- **D5 — n = 4 is excluded from GID adjudication.** At four points the NLSM amplitude is a
  polynomial (no poles) and there are no registered splits, so the fingerprint is degenerate;
  fit `n ∈ {5, 6}`, held-out `n = 8` as registered.
- **D6 — third dataset class.** WP3.4 (δ recovery) needs a positive instance; the dataset
  carries `TrPhi3_shifted` (finite registered δ = 7/3, withheld from the pass) in addition to
  the two classes named in WP2.7. NLSM's registered δ outcome is
  `NONIDENTIFIABLE(delta-underdetermined)`.
- **D7 — eq. (2.13) of arXiv:2405.09608 (index ranges of the vanishing mesh variables on split
  kinematics).** Our literal reading of the ranges does not reproduce the paper's own explicit
  examples (2.5)/(2.8); the registered split locus is therefore *derived exactly* from the
  linear map (2.10) (a certificate, not a sample test) and is checked to reproduce (2.5)
  verbatim. Filed as erratum-candidate E1 in edit-011; the factorization itself (eq. 1.7) is
  unaffected and holds exactly.
- **D8 — §9-OI-1 "stop and file before proceeding".** Erick was not available in-session; the
  proposed bound was registered, marked `[proposal]`, carried as `asm:B15-OI-1-pending` on the
  POS certificate/fact, and the sprint proceeded (the work is cheap to redo if the target is
  replaced). Same for the two thresholds (`asm:B15-OI-2-thresholds-pending` on GID).
